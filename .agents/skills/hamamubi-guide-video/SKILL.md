# はまむび！説明動画

実際の操作が伝わる、短く親しみやすい日英の説明動画を作る。既存の制作スクリプトを再利用する。
UI変更に伴う動画の鮮度確認にも使う。映画データの収集そのものには使わない。

## ユーザーの画面で勝手に再生しない

- ユーザーが「再生して」「聴かせて」などと明示的に依頼した場合だけ、ユーザーに見えるブラウザやプレイヤーで動画・音声を再生する。動画の作成・更新、UI修正、動作確認の依頼だけでは、画面上での再生や音を出す許可として扱わない。
- 通常の検証で既存のブラウザの再生ボタンを押したり、動画・音声プレイヤーを開いたりしない。ユーザーが見える再生を止めに入る必要がない進め方を守る。
- 必要な再生・シーク・字幕の検証は、隔離したheadlessブラウザでバックグラウンド実行し、すべての再生で `muted = true` を再生前に設定する。言語切替や再読み込みで作り直された動画にも適用する。既存の `scripts/site-guide/verify-playback.mjs` はこの方法で検証するため、優先して使う。headlessであることだけを無音の保証にしない。
- 動画への影響の照合は、ソース差分、既存の撮影素材、抽出フレーム、字幕・テキスト版、`ffprobe` などで進める。本番の確認にも同じ無音・バックグラウンドのルールを適用し、確認のためにユーザーの画面で再生しない。
- 音声の発音や声質の試聴が必要でも、勝手に音を出さない。自動解析の結果と、人が実際に聴いて確認した結果を区別し、無音の検証だけで試聴済みと報告しない。
- 動画・音声のプレビューは、ユーザーが求めた場合だけ提示する。無関係な修正の完了報告に動画プレビューを埋め込んだり、自動再生したりしない。

## 最初に判断すること

- 作業するcheckoutの `AGENTS.md` と [制作README](../../../scripts/site-guide/README.md) を読む。以下のコマンドはリポジトリルートで実行する。
- `shared/site-guide.json`、`scripts/site-guide/captures/manifest.json`、`public/guide/`、ローカルの音声キャッシュを確認する。既存の作業ブランチ・素材・ユーザーが選んだ声を引き継ぐ。
- 何を変えるかで工程を絞る。演出だけなら撮影・TTSをやり直さない。英語だけなら日本語の承認済みWAVを変えず、rendererにも `--lang en` を指定する。実UIが変わったら該当操作を撮り直す。
- `.wrangler/` と `output/` はGit管理外。別checkoutには声の素材がないことがある。まず既存の保存先を確認し、欠落を黙って別の声やBGMのみの動画で埋めない。

## 台本と演出

- 主機能は全映画館の上映予定を一望できるスケジュール。冒頭の挨拶の直後に「まずは、サイドバーから上映スケジュールを開いてみてね。」と操作へ誘い、マイページで表示する映画館を選ぶ操作と結果を続ける。作品検索から説明を始めない。

- 操作説明は実アプリを使う。似せて描いた架空UIで説明しない。映像内に「実画面／説明用データ」の制作注記は表示しない。素材の出典・説明用データの記録はmanifestとREADMEに残す。1場面1メッセージに絞り、「操作前 → 操作 → 結果」が追える画面と短い補足を組み合わせる。
- 冒頭は「横浜の映画館って、わくわくがいっぱい！ みんなにも知ってほしいな！」と子どもらしく気軽に話し、締めは「みんなの映画ライフを、たくさんサポートさせてね！ よろしく！ ばいばい〜！」という挨拶にし、最後の「ばいばい〜！」（英語は「Bye-bye!」）に1.5秒保持するウィンクを合わせる。選択済みの名前の発音を保つため、追加文だけ生成し、文間の無音で既存音声とつなぐ方法も使える。合成音声には元素材・切断位置を記録し、APIキャッシュのfingerprintを偽装しない。
- 自己紹介・締めの挨拶はマスコットの専用シーンにする。既存の `public/brand/` の通常・ウィンク素材を使い、不自然な手足を足さない。
- 現在の基準は、冒頭全体の緩やかな浮遊、話している間の上下動と傾き、最後に体を止めて1.5秒保持するウィンク。操作説明中も左上のマスコットを小さく動かす。動きはセリフの意図を支える程度にする。「跳ねる」という指定を毎秒の大ジャンプや常時点滅に置き換えない。回数・高さ・秒数は新しい依頼に合わせて調整する。
- 日本語の選択済みの声はLedaの明るく甘いアニメ寄り。「はまむび」は一つの固有名詞として平板型の発音が選ばれている。新たな指定がなければこの選択を維持する。声や発音を選び直すときだけ短い試聴を先に作る。
- 日本語と英語で意味・説明範囲・演出を揃える。英語は自然な英語の文章と抑揚にし、日本語の一人称・アクセント指示を流用しない。
- 作品詳細への移動、映画館サイトでのチケット購入、アプリ内の鑑賞予定登録を混同しない。字幕・読み上げ・テキスト版は `shared/site-guide.json` で揃える。

## 実画面を撮る場合

1. `capture.mjs` と `capture-fixture.mjs` を読み、現在のUIに操作対象と文言が合っているか確認する。APIだけを説明用データに置き換え、実画面の表示・操作を撮影する。
2. 撮影対象のローカルサーバーを起動する。Playwrightが見つからない場合は利用可能なruntimeを調べ、`PLAYWRIGHT_MODULE` にそのモジュールの絶対パスを指定する。個人のMacのパスをskillやソースに固定しない。
3. `GUIDE_URL`、撮影するcheckoutの `GUIDE_SOURCE_REVISION`、未コミット変更があれば `GUIDE_SOURCE_NOTE` を渡す。実行例は制作READMEを参照。過去のリビジョンをそのまま新しい撮影元として記録しない。
4. PNG、アクセシビリティスナップショット、注目箇所、操作時刻、出典情報を保存する。映画館の外部リンクは遷移確認までとし、予約を申し込まない。

撮影スクリプトは390×700・2倍解像度を前提にする。画面サイズを変えるならrendererの座標変換も合わせる。既存素材の単なる再合成に再撮影は不要。

## 音声を作る・修正する場合

[音声と言語・費用の手順](references/narration.md) を読む。要点は次のとおり。

- APIの `generation_config.speech_config[].language` に `ja-JP` / `en-US` を明示する。本文・style・キャッシュを言語ごとに分離する。英語に `boku` や日本語の固有名詞の発音指示を混ぜない。
- 発話本文と `speech_metadata.style` を分ける。英語のブランド名の途中に感嘆符などを置いて不自然な切れ目を作らない。
- `--dry-run` で対象の文・言語・声を確認し、必要な言語・場面だけ生成する。承認済み素材を別ディレクトリに保全し、変更後のリクエストを古いキャッシュのfingerprintとして偽装しない。
- 429ではAPIの待機指定を守る。既存スクリプトの間隔・再試行上限を使い、並列化やすぐの再実行で回避しない。
- 生成音声を確認する。英語版の全場面に別言語の混入がないか、冒頭の固有名詞が自然かを見る。APIパラメータの検査だけで発音品質を確認済みとしない。

## 合成と確認

詳細な依存・コマンド・出力仕様は [制作README](../../../scripts/site-guide/README.md) に従う。

```sh
python3 scripts/site-guide/render.py --stills --output-dir output/guide/stills
python3 scripts/site-guide/render.py --narration-dir .wrangler/site-guide-narration-mascot --output-dir output/guide/review
python3 -m unittest discover -s scripts/site-guide -p 'test_*.py'
```

上記の音声ディレクトリは既存素材の例。実際に使う、確認済みの `ja-NN.wav` / `en-NN.wav` を揃えた場所を指定する。仮出力では字幕テストは `public/guide/` を検査するので、候補を個別に確認し、採用して公開ファイルを差し替えた後にも実行する。

- `captures/manifest.json` の場面数・順序・長さを台本に合わせる。現在は11場面・89秒だが固定の制作要件ではない。構成を変える場合は撮影スクリプトと検証の期待値も合わせる。
- 各場面の音声開始は0.4秒後、音声の長さは場面長−0.8秒以内がrendererの契約。長すぎる音声を黙って切ったり倍速にしたりせず、文・読み上げ・場面長のどれを調整するか判断する。
- 着地、傾き、ウィンクを静止画だけでなく動く映像でも見る。音声内の先頭無音も含めて発話と動作を合わせる。音声のズレが撤回された場合など、不要なタイミング修正を続けない。
- 日英それぞれ、映像・ナレーション・VTT・テキスト版を照合する。画面の注目箇所、読みやすい文字、操作結果を見せる時間を確認する。
- `ffprobe` で900×1200、24fps、H.264/yuv420p、48kHzステレオAAC、タイムラインの尺、25MiB未満を検証する。仕様変更があればAboutのプレイヤーも検証する。
- 動画内に字幕があるため、プレイヤーの字幕トラックは読み込み時にオフにする。Macの字幕自動表示を想定し、手動でオンにした後は再生・シークでオフへ戻さない。
- 隔離したheadlessブラウザで `/#about` を320×700・390×844で開き、無音での日英再生、シーク、言語変更での再生位置リセット、全文表示、横溢れ、再読み込み、戻る・進むを確認する。
- 演出だけの更新で音声を維持するときは、修正前後の音声ストリームのハッシュ比較が使える。人の声だけでなくBGMも同じかを区別する。

## UI変更後の確認記録

- `npm run guide:check` が検出したソース・素材の差分を、日英の実画面と動画で照合する。共通ヘッダーの変更は映り込む全操作場面を確認する。
- 変更した操作場面を再撮影・再合成した後、配信用ビルドでも再生を確認する。声・台本が変わらなければ音声を再生成しない。
- 制作READMEの `guide:review` で変更箇所と確認結果を記録し、`ui-review.json` を同じPRに入れる。見た目が変わらない場合だけ、確認根拠を `--unchanged-visuals` で記録する。ハッシュを合わせるためだけの更新は禁止。
- このチェックは `ci:pr` に含まれる。画像・動画の意味的一致を自動証明する仕組みではないため、必要な照合・再生確認は上記の無音・バックグラウンドの方法で行う。

## 受け渡し

確認したMP4・WebP・VTTを `public/guide/` に反映し、台本・素材・手順を一緒にコミットする。途中のMP4や認証情報は入れない。
リポジトリの開発ルールに沿ってPR・CI・マージまで進め、CIが起動しない等の障害はコードの失敗と区別して報告する。デプロイ前はCloudflareの現在のProductionのSourceを確認し、そのコミットが配信候補の祖先かを `git merge-base --is-ancestor` で検証する。mainと本番の履歴が分岐していたら、そのままmainを配信せず既存の本番変更を保った候補を作る。マージ・デプロイ後は本番の `/#about` を確認する。

最終回答は今回変えた点、確認した範囲、追加費用（概算か実請求か）、公開状態を簡潔に伝える。動画プレビューを求められた場合だけ、絶対パスのプレビューを提示する。その場合はキャッシュを避けるため、`output/guide/` に版名を付けたコピーを作るとよい。
